# 보고서 작성·근거 정책

1. PR 하나를 업무 하나로 묶고 연결된 커밋은 독립 업무에서 제거합니다. 여러 PR과 연결된 동일 SHA는 가장 작은 PR 번호에 한 번 귀속합니다.
2. 독립 커밋은 잘못된 병합을 피하기 위해 한 건씩 유지합니다. Cross-PR 자동 결합, 추측성 다음 주 계획, 생산성 순위는 생성하지 않습니다.
3. LLM은 구조화 JSON 분석에만 사용합니다. 검증된 편집 가능 WorkItem으로 한국어 Markdown을 결정론적으로 렌더링합니다. 두 번째 자유 생성으로 사실이 바뀌지 않게 합니다.
4. LLM의 status와 contributors 변경, 알 수 없는 evidence ID, 한국어가 아닌 요약, 정량 성능 수치, URL/활성 코드 삽입, unsupported_claims가 있는 응답은 한 번 재요청 후 거부합니다.
5. 실패한 요약은 원문 기반 활동 설명과 `검증 필요`로 대체하고 Job은 partial입니다. 각 업무의 제목·요약에는 검증된 evidence 링크가 붙습니다. 기계 검증은 근거 ID 존재를 확인할 뿐 문장과 근거의 의미적 일치까지 입증하지 못합니다. 사람이 반드시 원문을 확인해야 합니다.
6. PR·커밋 텍스트는 system 명령으로 승격하지 않습니다. secret·토큰·이메일을 마스킹합니다. 모든 고객 식별자를 자동 탐지한다는 보장은 없으므로 조직의 데이터 분류 정책을 별도 적용하세요.
7. 기본 프롬프트 용어: PR, API, ROI, 클래스명 등 식별자 보존. 홍보성 표현과 근거 없는 개선율 금지.
8. 편집된 문장은 사용자 작성 내용입니다. 사실성은 편집·확정자가 확인합니다. 편집 전후 내용과 감사 기록을 보존합니다.
